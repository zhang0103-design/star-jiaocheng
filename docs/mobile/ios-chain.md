## 链式代理是怎么工作的

iOS 与 Android 的链式代理原理一致：

```text
手机
 ↓
第一跳代理（机场节点 · 负责出海）
 ↓
第二跳代理（代理 IP · 最终出口）
 ↓
目标网站
```

- **第一跳**：机场节点，负责出海。
- **第二跳**：代理 IP，负责作为最终出口。
- **出口 IP**：目标网站最终看到的 IP，等于第二跳的代理 IP。

## 操作前准备

1. **代理 IP 信息**：IP、端口、用户名、密码（协议为 SOCKS5）。
2. **机场订阅链接**：用于第一跳出海。

## 操作步骤（通用思路）

1. **添加第一跳**：在客户端导入机场订阅，获取出海节点。
2. **添加第二跳**：手动添加代理 IP（SOCKS5），填写 IP、端口、用户名、密码。
3. **设置链式关系**：在第二跳（代理 IP）的配置里，找到「前置代理 / 通过代理 / chain」等类似选项，选择第一跳的机场节点。
4. **启动代理**：连接第二跳配置。
5. **测试出口 IP**：打开 IP 查询网站，确认显示的 IP 等于代理 IP。
